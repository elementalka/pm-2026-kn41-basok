# S-11: локальний навчальний каталог

Поточний інкремент спринта1 від16.11.2026. **У роботі, не Done**: автоматичні перевірки пройшли, окремий огляд/приймання ще не відбулися. Чинна оцінка S-11 —5SP; вона не збільшувалася під зроблений код.

У каталозі можна створити аудиторію або обладнання, змінити назву й доступність, архівувати ресурс. Дані зберігаються в SQLite між відкриттями. Навчальний заявник читає активний каталог, а його прямі API-спроби запису отримують403. Історичне посилання на код переживає архівацію. Перевіряються три AC саме S-11, не весь CampusReserve.

## Запуск із кореня репозиторію

Python3.9+ зі стандартною бібліотекою, додаткових пакетів немає:

```powershell
python lr03_sprint_simulation/increment/catalogue/server.py
```

Відкрити `http://127.0.0.1:8731/`. Перемикач на сторінці обирає **fixture-роль** заявника/адміністратора; це спосіб відтворення тестового сценарію. Реального академічного входу, перевірки зайнятості в часі та допуску ІБ тут немає. Локальний сервер слухає тільки127.0.0.1. S-01/S-09 та виробниче приймання залишаються відкритими.

База `catalogue.sqlite3` створюється локально з [fixtures.json](fixtures.json) і не комітиться. Усі дані та demo-identity вигадані. Для окремої чистої перевірки можна вказати новий шлях: `python lr03_sprint_simulation/increment/catalogue/server.py --port 8732 --db C:/Users/Max/AppData/Local/Temp/catalogue-review.sqlite3`. Не потрібно видаляти робочу базу для тестів: автоматичні перевірки створюють власну тимчасову.

## Повторити автоматичні перевірки

```powershell
python -m unittest discover -s lr03_sprint_simulation/increment/catalogue -p test_catalogue.py -v
```

HTTP-сервер піднімається на випадковому локальному порту; перевіряються фактичні запити та стан БД, а не тільки виклики функцій. [Протокол](verification.md) пов’язує10 перевірок із трьома AC.
