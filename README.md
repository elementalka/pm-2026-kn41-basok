## Проєкт

CampusReserve — навчальний проєкт вебсервісу для господарської та навчальної частин академії. Він має об’єднати бронювання аудиторій і обладнання, показувати зайнятість ресурсів, запобігати подвійним бронюванням і підтримувати погодження заявок на великі аудиторії. Контекст теми 5 описує окремі паперові журнали та невдалу спробу вести спільну таблицю. Початкове рішення для першого релізу: перевірити повний шлях заявки в одному корпусі, з погодженням відповідальним працівником, а масштабування планувати за результатами пілота. Назва продукту й межа пілота є нашими проєктними припущеннями; приймання замовником ще не проводилось.

## Незмінні обмеження V03

Джерело: матеріали курсу, `home_works/LR01 Розбір провалу реального ІТ проєкту/lr01_variants.md`, рядок V03.

| Параметр | Значення |
| --- | --- |
| Команда | PM 50%; BA 50%; Dev 100%; Dev 100%; Dev 100%; QA 100% |
| Строк до першого релізу | 16 тижнів від погодженого старту |
| Початкова ємність двотижневого спринта | 30 SP |
| Стеля прямих витрат без contingency | 1 600 000 грн |

Сума зайнятості: **5 FTE**. Стеля годин: **5 × 16 × 40 = 3 200 год**. У горизонті релізу вміщується **16 / 2 = 8 спринтів**, початковий орієнтир — **8 × 30 = 240 SP**. Це розрахунок за варіантом, а не виміряна продуктивність і не обіцянка поставити такий обсяг. Детальний план, резерви та оцінки з’являться в наступних роботах.

## Перевірка

Із цієї папки, за наявності Python 3.9 або новішого:

```powershell
python tools/validate.py lr01_case
python tools/validate.py lr02_approach
```

Папка `tools` містить незмінені копії валідатора та схеми з матеріалів курсу. ЛР01 та ЛР02 проходять перевірку без помилок і попереджень. Повний запуск `python tools/validate.py` перевіряє також заготовки наступних робіт: 27 попереджень `empty` очікувані та не блокують здачу.

ЛР03 перевірена за вимогами журналу: десять розділів, оцінки всіх історій, ліміти днів, рішення за конвертами та докази готовності. Валідатор не має схеми для цього Markdown-журналу й не перевіряє його зміст.

Папки `lr01_case`–`lr18_closure` розташовані безпосередньо в корені репозиторію відповідно до [шаблону курсу](https://github.com/LyahovchukSergiy/pm-2026-template). Основна гілка — `main`.
